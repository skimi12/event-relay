## P0 初版の公開プレビュー

- 日本語の検索・詳細・出品フォーム・マイページ。
- デモを常に表示し、デモへの申込を拒否。
- 認証・D1・R2・サーバー入力検証・所有権認可。
- 実取引と課金を無効化した状態で公開。
- 型検査・境界テスト・DB整合性テスト・ビルド・ブラウザーQA。
- GitHubにソース、README、テスト、引継ぎ記録を投稿。

各項目の実際の完了状況はHANDOFFに記録します。

## P1 実証に使える運営機能

1. 下書きの編集・削除、アカウントのデータ削除手続、写真差替えと不要ファイル削除。
2. 当事者間の受渡確認、取消・期限切れの一貫処理、価格/条件の版管理。
3. 通報、掲載審査、管理者の監査履歴。企業確認の未実施/自己申告/確認済みを区別。
4. 不正投稿・過剰アクセスへの制限、検索のページング、写真の再エンコード/メタデータ除去。
5. 運営者情報と問い合わせ窓口を設定し、規約・プライバシー通知を実運用に合わせる。
6. 二つの別アカウントで、公開→申込→承認→引渡→双方完了と取消の本番相当E2E検証。

## P2 少人数での顧客検証

会場周辺と近接日程を限定し、実物10出品程度、有効な希望3社程度、期限内受渡2件程度を初回検証の仮の目安とします。市場の成立を証明する数値ではありません。

日時不一致、寸法不一致、運搬費、譲渡権限、会場の搬出条件、商品不足を失注理由として分類します。閲覧やお気に入り数だけで需要があると判断しません。

## P3 有料化

10%・15%などの手数料率は価格検証の候補です。運営時間、獲得費、決済手数料、返金・トラブル費用を含めて単位採算を測ります。

1. 支払主体・税込表示・契約成立時点・手数料発生条件・取消返金条件を確定。
2. マーケットプレイスに対応する決済設計と本番事業者契約。
3. webhook署名検証、冪等性、金額/通貨のサーバー照合、返金・台帳・監査。
4. テスト環境の支払/失敗/重複/返金を検証してから実課金。

実売上や支払意思が未確認なら、収益化済み・採算成立とは記録しません。
